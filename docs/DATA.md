# Data

All content lives in `src/data.json` — one file, currently ~1.3 MB: 5 countries, 7 cities,
234 places. There is no database. Editing content means running the app locally and letting
the dev API write the file, then committing the diff.

## Shape

```jsonc
{
  "countries": [
    {
      "id": "czech-republic",       // slug, unique among countries
      "name": "Czech Republic",     // base (English) name
      "nameHy": "Չեխիա",            // optional
      "nameRu": "Чехия",            // optional
      "flag": "https://…",          // image URL, shown as the flag chip
      "cities": [
        {
          "id": "prague",           // slug, unique within the country
          "name": "Prague",
          "nameHy": "Պրահա",        // optional
          "nameRu": "Прага",        // optional
          "image": "https://…",     // hero photo URL
          "landmarks": [
            {
              "id": "hradcanske-namesti-hradcany-square",  // slug, unique within the city
              "name": "Hradčanské náměstí (Hradčany Square)",
              "image": "https://…",
              "description": "…",        // Armenian original — the base text
              "descriptionEn": "…",      // optional translation
              "descriptionRu": "…",      // optional translation
              "coords": [50.0894, 14.3969],             // optional [lat, lon]
              "coordsText": "50°05'22.0\"N 14°23'49.0\"E", // what was pasted, kept for the edit dialog
              "day": null,               // legacy, unread
              "visited": false           // optional; absent on older records
            }
          ]
        }
      ]
    }
  ]
}
```

Everything is JSON-serialisable; the file is written back pretty-printed with 2-space
indentation (`vite.config.js`), so a content diff stays readable.

### Fields no code reads

`day` on places, and `notes` / `checklist` on cities. Leftovers from an earlier per-day
itinerary grouping that the current design flattened. Harmless, but don't build on them —
they are not wired to anything.

### Optional in practice

`visited` is present on 176 of 234 places; treat a missing value as `false`, which is what
the app does. `coords` is present on all but one place. `descriptionEn` is currently on
every place, `nameHy` / `nameRu` only where someone filled them in.

## Ids

Ids are generated by `slug()` in `src/App.jsx`, which runs the **English** name through
`latinize()` (`src/translit.js`) and reduces it to `[a-z0-9-]`, appending `-2`, `-3`… on a
collision within the same parent. `latinize()` folds Armenian, Russian/Ukrainian and Latin
diacritics first, so "Kraków" → `krakow` rather than `krak-w`, and an Armenian name produces
something readable instead of the `item` placeholder.

**Ids are load-bearing, in two places:**

1. `src/coords.js` (`COORDS`) is keyed by landmark id — ~60 built-in places.
2. The viewer-only reorder (`viewerOrder`) and the route selection are keyed by id.

An id is generated once, at creation, and never recomputed. So renaming a place through the
UI keeps its id — which is what you want. But if you edit `src/data.json` by hand and change
an id, **its `COORDS` entry no longer matches and the map pin disappears silently.** Either
update the `COORDS` key to match, or give the place its own `coords`, which takes precedence
over the table.

## Coordinates

Two sources, in priority order:

1. `landmark.coords` — `[lat, lon]`, entered per place in the edit dialog. Wins.
2. `COORDS[landmark.id]` in `src/coords.js` — the built-in table for older places.

The dialog accepts Google Maps' DMS format (`39°28'12.0"N 0°22'12.0"W`), parsed by
`parseDMS()`. The raw string is kept in `coordsText` so reopening the dialog shows what was
typed. A place with neither source is simply not pinned; the map caption says how many are
unlocated, and the place can't be added to a route.

## Images

Every image is a remote URL — no files are stored in the repo. Consequences worth knowing:

- Hosts do go dead; a broken photo is a data problem, not a code problem.
- The print/PDF path routes images through the `wsrv.nl` proxy for size and CORS
  (see `docs/ARCHITECTURE.md`), with the original URL kept as a fallback.
- Country `flag` and city `image` are plain URLs too, not codes or local assets.

## Adding content

The supported path is through the running app:

```bash
npm run dev          # http://localhost:<port>/Tripline/
```

Add / edit / reorder in the UI — `isOwner()` is true on localhost, so the controls appear and
each change is PUT to `/api/data`, which rewrites `src/data.json`. Then review and commit:

```bash
git diff --stat src/data.json
```

Hand-editing `src/data.json` also works and is sometimes faster for a bulk import — keep to
the shape above, generate ids the same way (lowercased, latinized, `[a-z0-9-]`, unique within
the parent), and remember that a bad id costs the map pin. The app re-reads the file when you
click the logo (`goHome()` flushes pending saves, then refetches), so an external edit shows
up without a browser reload.
